## 1. Обзор системы

### 1.1. Цели и задачи

**Цель:** Создание универсальной системы управления соревнованиями по художественной гимнастике с поддержкой правил FIG 2025-2028.

**Ключевые задачи:**
- Автоматизация организации соревнований (от регистрации до протоколов)
- Цифровизация судейства с минимизацией ошибок
- Работа в локальной сети с облачной синхронизацией
- Соответствие международным правилам FIG

### 1.2. Целевая аудитория

| Роль | Основные задачи |
|------|-----------------|
| **Организатор** | Создание соревнований, управление программой, экспорт данных |
| **Главный судья** | Формирование судейских бригад, контроль качества оценок |
| **Судья** | Выставление оценок (D, E, A) по правилам FIG |
| **Секретарь** | Приём оценок, формирование протоколов, работа с результатами |
| **Тренер/Зритель** | Просмотр результатов в реальном времени |

### 1.3. Ключевые возможности

#### Управление соревнованиями
- Создание соревнований с автогенерацией структуры
- Настройка программы (индивидуальное/групповое многоборье, финалы)
- Импорт/экспорт данных (Excel, CSV, JSON)
- Копирование структуры из предыдущих соревнований

#### Регистрация и жеребьевка
- Массовый импорт участников (Excel, CSV)
- Автоматическая жеребьевка с учётом правил
- Генерация стартовых протоколов
- Управление заменами и снятиями

#### Судейство по правилам FIG 2025-2028
- Бригады D (сложность), E (исполнение), A (артистизм)
- 3 варианта интерфейса: расширенный, базовый, упрощённый
- Автоматический расчёт консенсуса
- Валидация и блокировка некорректных оценок

#### Секретариат
- Приём оценок в реальном времени
- Автоматический расчёт итоговой оценки: `Total = D + (E-сбавки) + A`
- Формирование протоколов (PDF, Excel)
- Управление тай-брейками

#### Реальное время (WebSocket)
- Синхронизация оценок между устройствами
- Табло результатов для залов
- Мобильное приложение/сайт для зрителей
- Инфокиоски для участников

## 3. Основные модули

### 3.1. Управление соревнованиями

#### 3.1.1. Создание соревнования

**Обязательные поля:**
| Поле | Тип | Описание |
|------|-----|----------|
| Название | Текст | Полное название соревнования |
| Город, место | Текст | Локация проведения |
| Даты | Диапазон | Начало и окончание (дата >= сегодня) |
| Возрастные категории | Множественный выбор | Младшие, Девочки, Юниорки, Сениорки |

**Автогенерация при создании:**
1. **Структура дат:** Дни от начала до окончания (время старта: 09:00)
2. **Группы:** Для каждой категории создаются:
   - Индивидуальное многоборье
   - Финалы: скакалка, обруч, мяч, булавы, лента
   - Групповые упражнения (если выбрано)
3. **События:** Открытие (День 1), опробование площадки, награждение (последний день)

**Копирование из шаблона:**
- Структура групп, настройки регламента, судейские бригады (шаблон)
- НЕ копируются: участники, результаты, конкретные даты

#### 3.1.2. Программа соревнований

**Основные элементы:**

| Элемент | Описание | Параметры |
|---------|----------|-----------|
| **Группа/Поток** | Вид программы (многоборье, финал, группа) | Категория, возраст, тип |
| **День** | Дата проведения | Время начала/конца, количество потоков |
| **Событие** | Не-соревновательное мероприятие | Название, время, длительность |

**Регламентные параметры:**
```
Индивидуальное упражнение: 1'15"-1'30" (90 сек)
Групповое упражнение: 2'15"-2'30" (150 сек)
Разминка на ковре: 30 сек (индив.) / 60 сек (группа)
Перерыв между выступлениями: 3 мин
Время судьям на оценку: 2 мин
```

#### 3.1.3. Финальные соревнования

**Правила создания:**
- Отбор: топ-8 спортсменов по итогам квалификации
- Автоматический перенос участников
- Обнуление предыдущих результатов (fresh start)
- Виды: скакалка, обруч, мяч, булавы, лента (по отдельности)

### 3.2. Управление участниками

#### 3.2.1. Регистрация спортсменов

**Способы добавления:**
1. **Ручной ввод** (форма)
2. **Импорт из Excel/CSV** (массовая загрузка)
3. **Импорт из существующей базы** (национальные реестры)

**Обязательные поля:**
| Поле | Формат | Валидация |
|------|--------|-----------|
| ФИО | Текст | Не менее 2 слов |
| Дата рождения | Дата | Соответствие возрастной категории |
| Клуб/Регион | Текст | — |
| Разряд | Выбор | КМС, МС, МСМК и т.д. |

**Автоматическая проверка:**
- Дубликаты (по ФИО + дате рождения)
- Соответствие возраста категории (например, Юниорки: 13-15 лет)

#### 3.2.2. Жеребьёвка и стартовые протоколы

**Алгоритм жеребьёвки:**
```
1. Группировка участников по рейтингу (сеяные/несеяные)
2. Случайное распределение внутри групп
3. Минимизация конфликтов:
   - Одноклубники не выступают подряд
   - Равномерное распределение сеяных
4. Генерация стартовых номеров (001, 002, ...)
```

**Стартовый протокол содержит:**
- № п/п, ФИО, дата рождения, клуб, разряд
- Время выступления (расчётное)
- Поля для оценок судей (D, E, A)

### 3.3. Судейская система (FIG 2025-2028)

#### 3.3.1. Структура судейских бригад

| Бригада | Функция | Состав | Расчёт оценки |
|---------|---------|--------|---------------|
| **D-бригада** | Сложность | 2 судьи (D1, D2) | `D = (D1 + D2) / 2` |
| **E-бригада** | Исполнение | 4-6 судей | Среднее без макс/мин |
| **A-бригада** | Артистизм | 2-4 судьи | Консенсус или среднее |

**Итоговая оценка:**
```
Total = D + (10 - E_deductions) + A
```

#### 3.3.2. Интерфейсы судей

Система предлагает **3 варианта** интерфейса для разных уровней:

| Тип | Время ввода | Детализация | Применение |
|-----|-------------|-------------|------------|
| **Расширенный** | 2-3 мин | Полная (все элементы по FIG) | Национальные/международные соревнования |
| **Базовый** | 30-60 сек | Средняя (группы элементов) | Региональные соревнования |
| **Упрощённый** | 10-20 сек | Итоговая оценка | Локальные соревнования |

**Общие функции:**
- Автосохранение каждые 10 сек
- Таймер обратного отсчёта (2 мин)
- Блокировка после отправки
- История изменений (audit log)

**UI-компоненты:**
- Крупные кнопки (минимум 44×44 px для тач-экранов)
- Подсветка активного поля
- Визуальное подтверждение отправки

#### 3.3.3. Валидация оценок

**Автоматические проверки:**
```javascript
// D-бригада: сложность 0.0-20.0
if (D < 0 || D > 20) ERROR("D вне диапазона")

// E-бригада: сбавки 0.0-10.0
if (E_deductions < 0 || E_deductions > 10) ERROR("E вне диапазона")

// A-бригада: артистизм 0.0-10.0
if (A < 0 || A > 10) ERROR("A вне диапазона")

// Расхождение E-судей > 1.0
if (max(E_scores) - min(E_scores) > 1.0) WARNING("Большой разброс")
```

**Консенсус (при расхождениях):**
1. Система автоматически выявляет расхождения > 0.5 балла
2. Судьи видят значения друг друга (анонимно: E1, E2, E3...)
3. Возможность пересмотра оценки (1 раз)
4. Финальный расчёт: среднее без макс/мин

### 3.4. Секретариат

#### 3.4.1. Приём оценок

**Процесс:**
1. **WebSocket подключение:** Секретарь видит оценки судей в реальном времени
2. **Статусы:**
   - 🟡 Ожидание (судьи вводят оценки)
   - 🟢 Готово (все оценки получены)
   - 🔴 Консенсус (требуется пересмотр)
   - ⚫ Заблокировано (оценки приняты)

**Отображение на экране секретаря:**
| ФИО | D1 | D2 | E1 | E2 | E3 | E4 | A1 | A2 | Статус | Итого |
|-----|----|----|----|----|----|----|----|----|--------|-------|
| Иванова А. | 8.2 | 8.3 | -0.5 | -0.6 | -0.7 | -0.5 | 9.1 | 9.2 | 🟢 | **25.95** |

#### 3.4.2. Формирование протоколов

**Типы протоколов:**
1. **Стартовый** — Список участников с порядком выступления
2. **Промежуточный** — Результаты после N выступлений
3. **Итоговый** — Финальное ранжирование с местами
4. **Детальный** — Полная информация (все оценки судей)

**Форматы экспорта:**
- PDF (печать, официальный документ)
- Excel (дальнейшая обработка)
- JSON (интеграция с другими системами)
- HTML (публикация на сайте)

**Автоматический расчёт мест:**
```
1. Сортировка по Total (по убыванию)
2. При равенстве Total:
   a) Выше оценка E (исполнение)
   b) Выше оценка D (сложность)
   c) Выше оценка A (артистизм)
   d) Жеребьёвка (редко)
```

## 4. Правила ранжирования и оценок

### 4.1. Расчёт оценки D (сложность)

**По правилам FIG 2025-2028:**
```
D = D_body (база тела) + D_apparatus (работа с предметом) + D_dance (хореография)

D_body: сумма 9 самых сложных элементов (BD > 0)
D_apparatus: сумма элементов с предметом (AD/R)
D_dance: обязательные танцевальные элементы
```

**Судейство:**
- D1 и D2 выставляют независимо
- Финальная D = среднее арифметическое: `(D1 + D2) / 2`
- Разница > 0.5: обязательный консенсус

### 4.2. Расчёт оценки E (исполнение)

**Система сбавок (от 10.0):**
```
E = 10.0 - (сбавки за ошибки)

Мелкие ошибки: -0.1, -0.2, -0.3
Средние ошибки: -0.5
Крупные ошибки: -0.8, -1.0
Критические: -1.5+
```

**Расчёт консенсуса (4 судьи E1-E4):**
```
1. Убрать max и min значения
2. Среднее из оставшихся: E = (E2 + E3) / 2
```

**Пример:**
```
E1 = 9.2, E2 = 8.9, E3 = 8.8, E4 = 8.5
Убираем: 9.2 (max) и 8.5 (min)
E = (8.9 + 8.8) / 2 = 8.85
```

### 4.3. Расчёт оценки A (артистизм)

**Критерии (по FIG):**
- Музыкальность и выразительность
- Хореография и композиция
- Единство музыки и движения
- Оригинальность

**Судейство:**
- 2 судьи (A1, A2)
- A = (A1 + A2) / 2
- Диапазон: 0.0 - 10.0

### 4.4. Тай-брейк (при равенстве Total)

**Последовательность правил:**
1. **Выше E (исполнение)** — меньше ошибок
2. **Выше D (сложность)** — более сложная программа
3. **Выше A (артистизм)** — лучшая хореография
4. **Жеребьёвка** (если всё равно)

**Пример:**
| ФИО | D | E | A | Total | Место |
|-----|---|---|---|-------|-------|
| Иванова | 8.5 | 9.2 | 9.1 | 26.8 | 🥇 1 (выше E) |
| Петрова | 8.6 | 9.1 | 9.1 | 26.8 | 🥈 2 |

## 6. Анализ существующих систем

### 6.1. Международные решения

#### Longines Scoring System
- **Используется:** Олимпиады, Чемпионаты мира
- **Плюсы:** Официальная поддержка FIG, высокая надёжность
- **Минусы:** Очень дорого (€50k+), только для крупных турниров, проприетарная
- **Технологии:** Windows-only, локальная сеть

#### Swiss Timing
- **Используется:** Европейские чемпионаты
- **Плюсы:** Интеграция с медиа (трансляции), табло
- **Минусы:** Высокая стоимость, сложная настройка
- **Технологии:** Специализированное оборудование

### 6.2. Российские системы

#### "Артист" (Федерация РГ России)
- **Охват:** Всероссийские соревнования
- **Плюсы:** Адаптация под российские требования, поддержка ЕВСК
- **Минусы:** Устаревший интерфейс, нет мобильной версии
- **Технологии:** Desktop (Windows), MS Access

#### "Гимнаст" (региональный уровень)
- **Охват:** Локальные соревнования
- **Плюсы:** Простота, низкая стоимость
- **Минусы:** Нет автоматизации жеребьёвки, ручной ввод оценок
- **Технологии:** Excel-based
